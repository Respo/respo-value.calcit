# Upgrade to Calcit 0.13.77 / 升级到 Calcit 0.13.77

## English

- Aligned Calcit and `@calcit/procs` to exact 0.13.77 and advanced the immutable Respo provider from 0.16.90 to 0.16.91 while preserving module version 0.5.3.
- Canonical formatting produced no unrelated Snapshot changes. A real production-browser smoke exposed two legacy dynamic calls on `js/document`; both `mount-target` and `ssr?` now use the typed `js/document.querySelector` host boundary. The same smoke also caught the new optional `first` / `last` results crossing fixed two-item sample and map-entry boundaries, which are now explicitly unwrapped. Collection toggle handlers now assign the negated resolved boolean instead of passing `not` to an Option-valued map update callback; the exported vector component explicitly unwraps its required cursor so missing state fails fast instead of dispatching at the root, while data/fold state keep explicit defaulted Option boundaries.
- Marked the README component invocation as `cirru.no-check` because it is intentionally a partial consumer-side example requiring external `states` and `v` bindings.
- Selected exact GitHub Actions release versions (`actions/checkout@v4.4.0`, `actions/setup-node@v6.5.0`, and `calcit-lang/setup-calcit@v1.4.0`), disabled persisted checkout credentials and setup-node automatic package-manager caching, and added strict Caps/toolchain, dynamic-method, quality, and documentation gates.
- Replaced the deployment action that disabled SSH host verification with an explicit main-push-only rsync step. The reviewed public `tiye.me` ED25519 key is repository-pinned, uniquely selected, fingerprint-verified, and used with strict host checking; the private key remains in the existing secret.

## 中文

- 将 Calcit 与 `@calcit/procs` 精确对齐到 0.13.77，并把不可变 Respo provider 从 0.16.90 升级到 0.16.91；模块版本保持 0.5.3。
- canonical format 没有产生无关 Snapshot 变化。真实 production 浏览器 smoke 发现 `js/document` 上两处旧动态调用；`mount-target` 与 `ssr?` 现均使用 typed `js/document.querySelector` host boundary。同一次 smoke 还发现新版 `first` / `last` 的可选返回值越过固定二元 sample 与 map entry 边界，现已显式解包。集合折叠 handler 现直接写入已解析布尔值的反值，不再把 `not` 传给返回 Option 的 map update callback；导出的 vector 组件显式解包必需 cursor，使缺失状态直接失败而不会向根路径 dispatch，data/fold 状态则继续使用显式带默认值的 Option 边界。
- README 的组件调用依赖外部 `states` 与 `v`，本来就是消费者侧片段，现明确标记为 `cirru.no-check`。
- GitHub Actions 使用精确 release 版本号（`actions/checkout@v4.4.0`、`actions/setup-node@v6.5.0` 与 `calcit-lang/setup-calcit@v1.4.0`），关闭 checkout credential persistence 与 setup-node 自动 package-manager caching，并加入严格 Caps/toolchain、dynamic-method、quality 和文档门禁。
- 用显式、仅允许 main push 的 rsync 步骤替换会关闭 SSH host verification 的部署 action。经审阅的公开 `tiye.me` ED25519 key 固定在仓库中，要求唯一 host 条目并核验 fingerprint，再以 strict host checking 使用；私钥仍只来自现有 secret。
